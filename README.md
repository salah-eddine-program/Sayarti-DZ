# Sayarti DZ

تطبيق إدارة السيارة للجزائر: الصيانة، المصاريف، الوقود، الوثائق والتنبيهات، بثلاث لغات (العربية والفرنسية والإنجليزية).

## التشغيل

```bash
pnpm install --frozen-lockfile
cp .env.example .env
# أدخل إعدادات مشروع Supabase الخاص بك في .env محليًا فقط.
pnpm dev
```

المصادقة باستخدام **Supabase Auth بالبريد وكلمة المرور**. زر تسجيل الدخول يستعمل `prompt` بسيطًا. إذا كانت بيانات الدخول غير صحيحة، يُعرض خيار إنشاء حساب مع تأكيد كلمة المرور. Supabase لا يميّز علنًا بين الحساب غير الموجود وكلمة المرور الخاطئة منعًا لكشف الحسابات. عندما يكون تأكيد البريد مفعّلًا يجب تأكيد البريد قبل تسجيل الدخول. الـprompt ليس حقلاً مقنّعًا لكلمة المرور؛ يمكن استبداله لاحقًا بنموذج مقنّع دون تغيير خدمات المصادقة.

- `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` عامان ويُضمّنان وقت بناء الواجهة.
- `SUPABASE_URL` و`SUPABASE_ANON_KEY` على الخادم لنفس مشروع الواجهة.
- `SUPABASE_SERVICE_ROLE_KEY` **سر للخادم فقط**، لا تضفه مطلقًا إلى أي متغير `VITE_*` أو إلى Git.
- وضع العرض التجريبي لا يحتاج إعدادات Supabase؛ تسجيل الدخول والحفظ يحتاجان الإعدادات والخادم.

الواجهة ترسل `Authorization: Bearer <access_token>` إلى tRPC. الخادم يتحقق عبر `supabase.auth.getUser` ثم ينشئ/يحدّث `app_users`؛ جميع عمليات البيانات مقيّدة بـ`auth_user_id` موثوق. تُعاد أسماء الحقول بصيغة camelCase مع تواريخ `YYYY-MM-DD` للحفاظ على الواجهة.

## ترحيل قاعدة البيانات

لم يكن في المشروع ترحيل Postgres سابق. الترحيل الجديد هو:

`supabase/migrations/202610090001_sayarti.sql`

راجعه ثم طبّقه مرة واحدة على **مشروع Supabase فارغ** باستخدام SQL Editor أو Supabase CLI الذي تديره بنفسك. لم يُطبَّق تلقائيًا على أي قاعدة بعيدة. إذا كانت لديك الجداول مسبقًا، قارن المخطط أولًا ولا تُعد تنفيذ ترحيل الإنشاء. ينشئ الجداول `app_users` و`vehicles` و`maintenance` و`expenses` و`fuel_logs` و`documents`، مع RLS وفهارس ومفاتيح مركبة تمنع ربط سجل بمركبة لحساب آخر. إنشاء الملفات والتعديل يتم عبر tRPC؛ منح العميل مباشرةً محدود بالقراءة وإعدادات المستخدم غير الحساسة. لا يمنح العميل دور admin أو Premium.

**البيانات والحسابات القديمة لم تُنقل**: تحتاج عملية استيراد منفصلة وربط كل حساب بمعرّف Supabase Auth.

## الفحوص

```bash
pnpm check
pnpm test
pnpm build
```

بعد تغيير متغيرات `VITE_*` أعد بناء الواجهة. لتشغيل نسخة البناء استخدم `pnpm start`. الواجهة الثابتة وحدها (مثل GitHub Pages) لا تقدّم `/api/trpc`؛ يلزم خادم التطبيق لاستخدام ميزات الحفظ.

الخروج يبطل refresh token للجلسة الحالية عبر الخادم ثم `auth.signOut({ scope: "local" })` في العميل ويزيل ذاكرة بيانات الحساب. قد يبقى access token الصادر سابقًا صالحًا حتى انقضاء عمره حسب سلوك Supabase؛ اضبط عمر JWT وفق سياسة الأمان المطلوبة.

## الاشتراك والإشعارات

Premium معروض بسعر 500 دج سنويًا، لكن الدفع الحقيقي غير مفعّل. لا توجد mutation تمنح Premium من العميل؛ يجب إعداد بوابة دفع والتحقق من webhook قبل التفعيل. شكل استجابة `system.notifyOwner` محفوظ، لكنه يُرجع `success: false` لعدم إعداد مزوّد إشعارات خارجي؛ التنبيهات المرئية ضمن الواجهة محفوظة.

## Android

نسخة الويب قابلة للتثبيت كـPWA. ملف GitHub Actions في `.github/workflows/android-apk.yml` يجهز Capacitor ويبني APK بعد توفير رابط خادم التطبيق في متغير `APP_SERVER_URL`. يجب توفير متغيرات Supabase العامة أثناء بناء الواجهة على CI، والخاصة على الخادم فقط. لا تُعتبر العملية ناجحة إلا عند تنزيل artifact فعلي.
